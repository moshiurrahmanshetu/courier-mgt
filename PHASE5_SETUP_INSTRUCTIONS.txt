DELIVERABLE CHECKLIST:
=====================
After setup, the following should work end-to-end:

1. Logged in as Admin/Staff with delivery permission: "Delivery" menu section appears with Staff Workload, Assign Parcels, All Deliveries links
2. Staff Workload page shows correct active/delivered/failed counts per delivery staff member
3. Can assign a picked_up/in_transit parcel to a delivery staff member from assign.php, and this creates a log entry with the assignment note
4. All Deliveries list shows all assigned parcels with correct filters working
5. Logged in as a Delivery Staff user: "My Deliveries" is the menu item shown (not the Admin delivery section), and visiting assign.php/staff-list.php/assigned-list.php directly redirects away or is blocked

7. Delivery Staff can update status only for their own assigned parcels, only through valid transitions (out_for_delivery -> delivered/failed_delivery, failed_delivery -> out_for_delivery)
8. Attempting to access update-delivery-status.php for a parcel NOT assigned to the logged-in delivery staff user is blocked with access denied
9. Marking failed_delivery without a note is rejected (note required for that specific transition)
10. Delivery Staff dashboard.php shows their personal quick-glance summary cards with correct real counts
11. No raw PHP/SQL errors ever shown to browser at any point

DELIVERY MODULE FILES:
=====================
/modules/delivery/
- staff-list.php - Admin/Staff view of delivery staff workload
- assign.php - Assign parcels to delivery staff
- assigned-list.php - All assigned parcels list
- my-deliveries.php - Delivery Staff personal dashboard
- update-delivery-status.php - Delivery Staff status updates

ACCESS CONTROL DESIGN:
=====================
Two different permission contexts:
a) hasPermission($pdo, 'delivery', 'view') / 'edit' - for Admin/Staff pages
b) hasRole(['Delivery Staff']) - for Delivery Staff exclusive pages

Delivery Staff pages:
- my-deliveries.php - ONLY for Delivery Staff role
- update-delivery-status.php - ONLY for Delivery Staff role
- Security check: parcel must be assigned to logged-in user

Admin/Staff pages:
- staff-list.php - Requires delivery.view permission
- assign.php - Requires delivery.edit permission
- assigned-list.php - Requires delivery.view permission

STATUS TRANSITION RULES FOR DELIVERY STAFF:
============================================
Narrower than full Phase 4 rules:
- out_for_delivery → delivered
- out_for_delivery → failed_delivery (note required)
- failed_delivery → out_for_delivery (re-attempt)

Any other status: blocked with message "not currently available for delivery status update"

SIDEBAR UPDATE:
===============
For Admin/Staff (hasPermission($pdo, 'delivery', 'view')):
- Shows "Delivery" menu section with:
  - Staff Workload (staff-list.php)
  - Assign Parcels (assign.php)
  - All Deliveries (assigned-list.php)

For Delivery Staff (hasRole(['Delivery Staff'])):
- Shows single "My Deliveries" menu item (my-deliveries.php)
- Admin/Staff delivery section NOT shown
- This is their primary/dashboard menu

MUTUALLY EXCLUSIVE:
The two menu conditions are mutually exclusive:
- Delivery Staff sees only "My Deliveries"
- Admin/Staff sees only "Delivery" section
- Both conditions don't show for same user

DASHBOARD UPDATE:
=================
For Delivery Staff role users:
- Shows 3 summary cards:
  - Pending Delivery Count (parcels in picked_up/in_transit/out_for_delivery)
  - Delivered Today Count (delivered status with today's updated_at)
  - Failed Delivery Count (failed_delivery status)
- Each card has a button to view that category in My Deliveries

For Admin/Staff:
- Dashboard unchanged from Phase 1 (placeholder stats)
- Full stats dashboard to be built in later phase

PARCEL VIEW UPDATE:
===================
Updated /modules/parcels/view.php to allow Delivery Staff access:
- Original check: hasPermission($pdo, 'parcels', 'view')
- New carve-out: Delivery Staff can view parcels assigned to them
- Security: delivery_staff_id must equal session user_id
- Additional "Update Delivery Status" button for Delivery Staff
- Back link changes to "My Deliveries" for Delivery Staff

ASSIGNMENT LOGGING:
===================
When assigning parcels to staff:
- Updates parcels.delivery_staff_id
- Inserts parcel_status_log entry with:
  - Same current_status (no status change)
  - Note: "Assigned to [Staff Name]"
  - changed_by: session user_id
- This creates timeline entry for assignment event

STAFF WORKLOAD PAGE:
===================
Shows delivery staff users with:
- Staff Name, Phone, Email
- Active Assigned (picked_up + in_transit + out_for_delivery)
- Total Delivered (all-time delivered count)
- Total Failed (all-time failed count)
- Status (Active/Inactive from users.is_active)
- No add/edit user functionality (use User Management)

ASSIGN PARCELS PAGE:
===================
Shows parcels in status: picked_up or in_transit
Columns: Tracking #, Receiver Name, Address, Status, Currently Assigned
Each row has:
- Delivery staff dropdown
- "Assign" button
- Assignment independent of status change
- Creates log entry for assignment event

ALL DELIVERIES PAGE:
====================
Shows ALL parcels with delivery_staff_id NOT NULL
Columns: Tracking #, Receiver Name, Phone, Delivery Staff, Status, Booking Date, Expected Delivery
Filters:
- By Delivery Staff (dropdown)
- By Status (dropdown)
- By Date range
Server-side pagination (15 per page)
Action: View (links to parcels/view.php)

MY DELIVERIES PAGE (Delivery Staff Dashboard):
===============================================
Shows ONLY parcels where delivery_staff_id = session user_id
Tabs/Filter buttons:
- Today's Assigned (expected_delivery_date = today OR booking_date = today)
- Pending Delivery (status = picked_up/in_transit/out_for_delivery)
- Delivered (status = delivered)
- Failed Delivery (status = failed_delivery)
Table columns: Tracking #, Receiver Name, Phone, Address, COD Amount, Status
Actions: View, Update Status (only for out_for_delivery/failed_delivery)

UPDATE DELIVERY STATUS PAGE:
===========================
Restricted to Delivery Staff role
Security check: parcel.delivery_staff_id must equal session user_id
Only allows specific transitions:
- out_for_delivery → delivered
- out_for_delivery → failed_delivery (note REQUIRED)
- failed_delivery → out_for_delivery (re-attempt)
Other statuses: blocked with message
Transaction-based updates
Redirects back to my-deliveries.php

IMPORTANT NOTES:
===============
- All database queries use PDO with prepared statements
- Assignment is independent of status change
- Status timeline reflects assignment events
- Delivery Staff can only update their own assigned parcels
- Note required for failed_delivery transition
