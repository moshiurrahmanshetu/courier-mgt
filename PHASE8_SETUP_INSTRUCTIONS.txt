COURIER MANAGEMENT SYSTEM - PHASE 8 SETUP INSTRUCTIONS
========================================================

PHASE 8 SCOPE: Installer / Setup Wizard

SETUP STEPS:
============

This phase is included in the project distribution and is automatically triggered for fresh installations. No manual setup steps are required - the installer will run automatically when a fresh copy of the project is accessed.

WHAT THE INSTALLER DOES:
========================

1. AUTOMATIC INSTALLER TRIGGER:
   - Fresh copy (no config.php, no installed.lock): Automatically redirects to /installer/index.php
   - Already installed copy: Goes straight to login.php (installer is blocked)

2. STEP 1 - WELCOME & REQUIREMENTS CHECK:
   - Checks PHP version >= 7.4
   - Checks mysqli extension
   - Checks PDO and pdo_mysql extensions
   - Checks GD extension
   - Checks folder write permissions (config, avatars, installer/tmp)
   - Blocks proceeding if any check fails

3. STEP 2 - DATABASE CONFIGURATION:
   - Database Host (default: localhost)
   - Database Port (default: 3306)
   - Database Name (required)
   - Database Username (required)
   - Database Password (optional)
   - SQL File Upload (.sql only)
   - Test Connection button (AJAX, validates credentials and database existence)
   - Import button disabled until both test passes AND file is selected

4. STEP 3 - SQL IMPORT:
   - Validates uploaded .sql file
   - Moves to /installer/tmp/ temporarily
   - Executes SQL using mysqli::multi_query()
   - Handles multi-statement dump files correctly
   - Processes all result sets
   - Deletes temp file after successful import
   - Logs errors to /installer/tmp/import-error.log if import fails

5. STEP 4 - ADMIN ACCOUNT SETUP:
   - Full Name, Username, Email, Password, Confirm Password
   - Validation: password minimum 8 characters, passwords must match
   - Deletes existing admin users from imported database
   - Creates new admin account with bcrypt password hash
   - Uses transaction to ensure atomic operation

6. STEP 5 - FINISH & CONFIG WRITE:
   - Automatically generates /config/config.php with entered DB credentials
   - Creates /config/installed.lock file (installation timestamp)
   - Clears installer session variables
   - Shows success screen with admin username
   - "Go to Login" button
   - "Secure My Installation" button (optional cleanup)

7. CLEANUP (OPTIONAL):
   - Deletes all installer files except index.php
   - Replaces index.php with simple redirect to login.php
   - Prevents re-access to installer after installation

IMPORTANT FILE CHANGES:
=======================

1. config/config.php → config/config.sample.php:
   - Renamed to become a template/reference
   - Added DB_PORT constant
   - Used by installer as template for generating live config.php

2. New config/config.php:
   - Generated by installer during step 5
   - Contains actual DB credentials entered by buyer
   - Should be backed up by buyer after installation

3. New config/installed.lock:
   - Created by installer upon successful completion
   - Contains installation timestamp
   - Mere existence = system is installed (lock mechanism)

4. New /installer/ folder:
   - Contains all installer wizard files
   - Should be deleted manually or via cleanup button after installation
   - Index.php replaced with redirect after cleanup

SECURITY MECHANISMS:
===================

1. LOCK FILE PROTECTION:
   - Every installer file checks for installed.lock before executing
   - If lock exists, redirects to login.php immediately
   - Prevents re-running installer after installation

2. SESSION-BASED CREDENTIALS:
   - DB credentials stored in $_SESSION during installer
   - Re-validated on each step (never trust blindly)
   - Cleared after installation completes

3. AJAX VALIDATION:
   - Test connection runs server-side validation
   - Import button requires both successful test AND file selection
   - No direct access to database operations without validation

4. FILE UPLOAD VALIDATION:
   - Must be .sql extension
   - Size checked against PHP upload limits
   - Moved to temp directory for processing
   - Deleted immediately after import

5. CLEANUP OPTION:
   - Optional security feature to remove installer files
   - Leaves minimal redirect-only index.php
   - Prevents accidental re-exposure of installer

FOR THE BUYER (Distribution):
==============================

When distributing this project:

1. Include ALL files in the ZIP
2. Ensure config.php is RENAMED to config.sample.php
3. Ensure installed.lock does NOT exist
4. Include /installer/ folder with all its contents
5. Provide instructions:
   - Extract ZIP to server
   - Visit the URL
   - Follow the 5-step wizard
   - Export your database as a single .sql dump file
   - Upload during step 2
   - Set up admin account
   - Complete installation
   - Optionally run cleanup

DATABASE EXPORT INSTRUCTIONS FOR BUYER:
=====================================

To export the complete database:

1. Using phpMyAdmin:
   - Select the database
   - Click "Export" tab
   - Select "Custom" export method
   - Select all tables
   - Enable "Structure" and "Data"
   - Enable "DROP TABLE / VIEW / PROCEDURE / FUNCTION"
   - Format: SQL
   - Click "Go"
   - Save the .sql file

2. Using mysqldump (command line):
   ```bash
   mysqldump -u username -p database_name > backup.sql
   ```

3. The exported file should contain:
   - CREATE TABLE statements for all tables
   - INSERT statements for all data
   - Complete schema and seed data
   - No dependency on the phase-by-phase .sql files

TESTING THE INSTALLER:
======================

To test the installer flow:

1. Ensure config.php is renamed to config.sample.php
2. Delete installed.lock if it exists
3. Export your current database as a single .sql file
4. Visit the site root - should redirect to installer
5. Run through all 5 steps
6. Verify login works with new admin credentials
7. Verify old admin credentials no longer work
8. Test cleanup functionality
9. Verify re-visiting installer redirects to login

DELIVERABLE CHECK FOR THIS PHASE:
=====================================

After building, the following must work end-to-end:

1. Fresh copy automatically redirects to installer (not login)
2. Step 1 correctly detects and displays system requirements
3. Step 2: wrong credentials show failure, correct credentials show success
4. Step 2: Import button disabled until test passes AND file selected
5. Step 3: uploads and imports single .sql dump file successfully
6. Step 4: creates new admin, removes old seeded admin
7. Step 5: generates config.php and installed.lock
8. After installation, installer redirects to login
9. Site root goes to login (not installer) after installation
10. Cleanup button successfully removes installer files
11. New admin login works, old credentials don't
12. No raw PHP/SQL/mysqli errors shown during installation
