COURIER MANAGEMENT SYSTEM - PHASE 3 SETUP INSTRUCTIONS
========================================================

PHASE 3 SCOPE: Dynamic Role & Permission Management

SETUP STEPS:
============

1. DATABASE UPDATE:
   - Import the SQL file: database/roles_permissions.sql into your existing database
   - This will create the permissions and role_permissions tables
   - This will also seed the permission system with 24 permissions (6 modules x 4 actions)
   - This will assign default permissions to Admin, Staff, and Delivery Staff roles

2. VERIFY CONFIGURATION:
   - Ensure config/config.php has correct database credentials
   - The system should already be configured from previous phases

3. ACCESS THE APPLICATION:
   - Open in browser: http://localhost/courier-mgt/
   - Login with admin credentials (username: admin / password: Admin@123)

DELIVERABLE CHECKLIST:
=====================
After setup, the following should work:

1. Logged in as Admin, "Role & Permission" menu appears; logged in as Staff or Delivery Staff, it does NOT appear, and direct URL access redirects away
2. Can view list of roles (Admin, Staff, Delivery Staff already seeded, showing correct user counts)
3. Can create a brand new custom role (e.g. "Accountant") and immediately land on its permission assignment page
4. Can check/uncheck permission checkboxes in the matrix and save — reloading the page shows the saved state correctly
5. Can edit a role's name/description
6. Attempting to delete a role that has users assigned shows a blocking error message
7. Deleting a role with zero users assigned works and removes it from the list
8. Logging out and back in as Staff still correctly shows/hides Customers menu and correctly allows/blocks create/edit/delete actions based on whatever permissions were assigned to Staff role
9. No raw PHP/SQL errors ever shown to browser at any point

NEW FEATURES IN PHASE 3:
=========================
- Dynamic permission system with module-action granularity
- Permission matrix UI for assigning permissions to roles
- Session-cached permissions for performance
- Permission checks using hasPermission() function
- Role management (create, edit, delete with safety checks)
- Retrofitted Customer module to use permission system
- Admin-only access to Role & Permission management

PERMISSIONS STRUCTURE:
=====================
6 Modules with 4 Actions Each (24 Total Permissions):
- users (User Management): view, create, edit, delete
- customers (Customer Management): view, create, edit, delete
- parcels (Parcel Management): view, create, edit, delete
- delivery (Delivery Management): view, create, edit, delete
- payments (Payment Management): view, create, edit, delete
- reports (Reports): view, create, edit, delete

DEFAULT PERMISSION ASSIGNMENTS:
==============================
- Admin: ALL 24 permissions
- Staff: customers.* (4), parcels.* (4), delivery.view, payments.view (10 total)
- Delivery Staff: delivery.view, delivery.edit (2 total)

HOW TO USE PERMISSION SYSTEM:
===========================
Instead of using hasRole(['Admin', 'Staff']), use:
hasPermission($pdo, 'module_key', 'action')

Examples:
- hasPermission($pdo, 'customers', 'view') - Check if user can view customers
- hasPermission($pdo, 'users', 'create') - Check if user can create users
- hasPermission($pdo, 'parcels', 'delete') - Check if user can delete parcels

IMPORTANT NOTES:
===============
- All database queries use PDO with prepared statements
- Permission checks first use session-cached data for performance
- Fallback to DB query if session data is missing
- Roles with assigned users cannot be deleted (safety check)
- Admin role permissions can be modified but shows warning
- Permission changes refresh session automatically for current user
- The same professional design theme from previous phases is maintained
- hasRole() function is still available for direct role checks where appropriate
