COURIER MANAGEMENT SYSTEM - PHASE 2 SETUP INSTRUCTIONS
========================================================

PHASE 2 SCOPE: Customer Management Module

SETUP STEPS:
============

1. DATABASE UPDATE:
   - Import the SQL file: database/customers.sql into your existing database
   - This will create the customers table
   - No seed data is included - the table starts empty

2. VERIFY CONFIGURATION:
   - Ensure config/config.php has correct database credentials
   - The system should already be configured from Phase 1

3. ACCESS THE APPLICATION:
   - Open in browser: http://localhost/courier-mgt/
   - Login with admin credentials (username: admin / password: Admin@123)

DELIVERABLE CHECKLIST:
=====================
After setup, the following should work:

1. Logged in as Admin or Staff, "Customers" menu item appears in sidebar
2. Logged in as Delivery Staff, Customers menu item does NOT appear, and direct URL access redirects with access denied message
3. Can add a new customer, customer_code auto-generates correctly and sequentially (CUS-0001, CUS-0002...)
4. Can search customers by name/phone/code
5. Can filter by status (Active/Inactive)
6. Can edit a customer and changes save correctly
7. Can view a single customer's full details
8. Can soft delete a customer (disappears from default list) and restore it (reappears) via the "Show Deleted Customers" toggle
9. Pagination works correctly when there are more than 15 customers
10. All forms have both client-side and server-side validation, with clean error messages

NEW FEATURES IN PHASE 2:
=========================
- Customer management module with full CRUD operations
- Auto-generated customer codes (CUS-XXXX format)
- Soft delete and restore functionality
- Advanced search and filtering
- Server-side pagination (15 per page)
- Role-based access control (Admin/Staff only)
- Flash message system for success/error notifications
- Extended form validation for customer forms
- Placeholder for future Parcel History integration

PERMISSIONS:
============
- Admin: Full access to customer management
- Staff: Full access to customer management (same as Admin)
- Delivery Staff: NO access to customer management

DATABASE STRUCTURE:
==================
Table: customers
- id (PK, auto increment)
- customer_code (varchar, unique) - Auto-generated CUS-XXXX
- full_name (varchar)
- phone (varchar)
- email (varchar, nullable)
- address (text)
- city_area (varchar)
- status (enum: 'active', 'inactive')
- is_deleted (tinyint) - For soft delete
- created_by (int) - User ID who created the record
- created_at (timestamp)
- updated_at (timestamp)

IMPORTANT NOTES:
===============
- All database queries use PDO with prepared statements
- No foreign key constraints to users table (created_by is stored as int)
- Flash messages are stored in session and displayed once then cleared
- Customer codes are generated sequentially with 4-digit zero padding
- Soft delete uses is_deleted flag (0 = active, 1 = deleted)
- The same professional design theme from Phase 1 is maintained
- No new color schemes introduced - uses existing muted teal accent
