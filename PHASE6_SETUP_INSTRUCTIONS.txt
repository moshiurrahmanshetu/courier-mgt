DATABASE STRUCTURE:
===================
payments table:
- id (PK, auto increment)
- parcel_id (FK -> parcels.id, ON DELETE CASCADE, UNIQUE)
- delivery_charge (copied from parcel for historical accuracy)
- cod_amount (copied from parcel for historical accuracy)
- paid_amount (amount actually paid/collected so far)
- due_amount (calculated as delivery_charge + cod_amount - paid_amount)
- payment_status (enum: unpaid, partial, paid, cod_pending, cod_collected)
- payment_method (varchar, nullable)
- payment_date (date when fully settled)
- notes (text, nullable)
- created_by (user id who created the record)
- created_at, updated_at

payment_transactions table:
- id (PK, auto increment)
- payment_id (FK -> payments.id, ON DELETE CASCADE)
- amount (amount of this specific transaction)
- payment_method (varchar, nullable)
- transaction_note (varchar, nullable)
- recorded_by (user id who recorded the transaction)
- recorded_at (timestamp)

PAYMENT STATUS LOGIC:
========================
The payment status is automatically calculated based on paid_amount vs total due:
- paid_amount == 0 AND cod_amount > 0 → 'cod_pending'
- paid_amount == 0 AND cod_amount == 0 → 'unpaid'
- paid_amount > 0 AND paid_amount < total_due → 'partial'
- paid_amount >= total_due AND cod_amount > 0 → 'cod_collected'
- paid_amount >= total_due AND cod_amount == 0 → 'paid'

payment_date is set when status becomes 'paid' or 'cod_collected' (fully settled).

LAZY CREATION APPROACH:
==========================
Payment records are auto-created on first access:
- When a parcel's payment page is accessed for the first time
- getOrCreatePaymentRecord() function handles this
- Copies delivery_charge and cod_amount from parcel
- Sets initial status based on cod_amount presence
- Avoids modifying Phase 4 files unnecessarily

HELPER FUNCTIONS:
=================
getOrCreatePaymentRecord($pdo, $parcelId):
- Gets existing payment record or creates new one
- Copies delivery_charge and cod_amount from parcel
- Sets initial status based on cod_amount
- Returns payment record data

recalculatePaymentStatus($pdo, $payment_id):
- Sums all transactions for the payment
- Updates paid_amount and due_amount
- Determines and updates payment_status
- Sets payment_date when fully settled
- Called after every transaction insert

getPaymentStatusBadgeClass($status):
- Returns Bootstrap badge color class for status

formatPaymentStatus($status):
- Returns formatted status label for display
