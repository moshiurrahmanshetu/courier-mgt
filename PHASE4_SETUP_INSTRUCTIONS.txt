DATABASE STRUCTURE:
===================
parcels table:
- id (PK, auto increment)
- tracking_number (unique, auto-generated)
- customer_id (FK -> customers.id, ON DELETE RESTRICT)
- receiver_name, receiver_phone, receiver_address
- parcel_type, parcel_description, weight
- delivery_charge, cod_amount
- delivery_staff_id (FK -> users.id, ON DELETE SET NULL, nullable)
- booking_date, expected_delivery_date
- current_status (enum: pending, picked_up, in_transit, out_for_delivery, delivered, failed_delivery, cancelled)
- is_deleted (soft delete flag)
- created_by, created_at, updated_at

parcel_status_log table:
- id (PK, auto increment)
- parcel_id (FK -> parcels.id, ON DELETE CASCADE)
- status (enum, same as parcels.current_status)
- note (optional note, e.g., reason for failed delivery)
- changed_by (user id who made the change)
- changed_at (timestamp)

STATUS TRANSITION RULES:
========================
pending → picked_up, cancelled
picked_up → in_transit, cancelled
in_transit → out_for_delivery, cancelled
out_for_delivery → delivered, failed_delivery
failed_delivery → out_for_delivery (re-attempt), cancelled
delivered → (final, no further transitions)
cancelled → (final, no further transitions)

TRACKING NUMBER GENERATION:
===========================
Format: TRK-XXXX (4-digit zero-padded number)
Examples: TRK-0001, TRK-0002, TRK-0003, etc.
Logic: Query MAX numeric part from existing tracking numbers, increment by 1
Fallback: TRK-0001 if table is empty or error occurs
